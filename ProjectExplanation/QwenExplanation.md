# Qwen2.5-VL Integration in SMT
 
 This document outlines the architecture wrapper, integration components, and specific data maneuvers required to mount the `Qwen2_5_VLForConditionalGeneration` model into the SMT (Sheet Music Transformer) project. This ensures multimodal training on sheet music images alongside text sequences.
 
 ## 1. Core Integration File
 The wrapper implementation resides at: `smt_model/architectures/qwen25_vl_arch.py`. This class is registered to the `smt_model/architectures/builder.py` under the `'qwen'` key.
 
 The `Qwen2_5_VLWrapper` complies with the standard SMT inference and training APIs, namely handling:
 * `encoder_input`: 2D tensor representations of sheet music images.
 * `decoder_input`: Target sequences mapped to token indices.
 * Autoregressive step generation logic (`predict()`).
 
 ## 2. Vision and Token Management
 Qwen2.5-VL requires special vision tokens injected into the main sequence. Because the SMT dictionary changes depending on the training corpus, the wrapper automatically extends the config vocabulary size by 3 and injects custom IDs to handle:
 * `<|vision_start|>`
 * `<|image_pad|>`
 * `<|vision_end|>`
 
 Furthermore, the token IDs (`vision_start_token_id`, `vision_end_token_id`, `image_token_id`) must match the Hugging Face configuration correctly.
 
 ## 3. Tensor Pre-processing & Patching
 Hugging Face's Qwen2.5-VL natively expects `pixel_values` patched by the vision encoder and a grid structure defining the dimensions (`image_grid_thw`).
 
 ### The Patching Operation
 The wrapper intercepts 1-channel (grayscale) sheet music images passed from the SMT dataloader and performs a dynamic transformation:
 
 1. **Padding**: Images are inherently padded to be divisible by 32 (where `<patch_size=14 * 2>` + some temporal adjustments).
 2. **Expansion**: The 1-channel grayscale image is copied into 3 RGB channels (`input.unsqueeze(1).expand(-1, 3, -1, -1)`).
 3. **Unfolding / Tiling**: Applying patches of size `14x14` using PyTorch's `unfold`.
 4. **Reshaping**: `[batch, num_patches, channels * patch_size * patch_size]` -> resulting in `pixel_values`.
 5. **Grid Tensor (`image_grid_thw`)**: Defines the physical block constraints `(temporal=1, height_blocks, width_blocks)` which perfectly informs the `mrope_section` for rotation embeddings regarding physical shapes.
 
 ### Input IDs Construction
 For each item in the batch, the wrapper injects the image representation into the model's sequence inputs:
 ```text
 <bos> <|vision_start|> <|image_pad|> * (num_patches) <|vision_end|> ... [Text Protocol]
 ```
 The length of `num_patches` generated by unfold matches precisely the temporal requirement evaluated by `get_placeholder_mask()`.
 
 ## 4. Attention & Rotated Positional Embedding configuration
 To prevent a known dynamic sizing initialization error with DeepSpeed/Hugging Face models (`KeyError: 'mrope_section'` or generic duplication issues upscaling sum length dynamically), the configuration explicitly sets `rope_scaling={"type": "mrope", "mrope_section": [8, 12, 12]}`. 
 
 This sums up to `32` per chunk, duplicated across keys/queries properly mapping the vision sequence embeddings.
 
 ## 5. Autoregressive Inference (Predict)
 The wrapper's `predict()` iteratively expands upon the input prompt by forwarding the `pixel_values` repeatedly (or maintaining past key values when implemented fully). Currently, the iterative generation correctly utilizes the `SMTOutput` protocol required by upstream training evaluation checkpoints.
